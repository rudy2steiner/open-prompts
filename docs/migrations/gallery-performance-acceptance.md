HTTP返回、缓存内部处理和浏览器首屏绘制是不同指标。不能用375ms HTTP样本宣称首屏绘制完成，不能用复用连接样本替代冷连接，也不能把有公开页面缓存的首次访客与完全冷边缘请求混为一谈。目标保持未完成，待排除浏览器限速/网络不稳定后继续真实首开与正式登录检查。

## 复测方法

1. 确认正式部署完成、维护关闭，且Chrome文档为visible。
2. 在正式域名直接打开Gallery，记录TTFB、FCP、首屏18张卡片和预览可见状态。记录HTML缓存HIT/MISS、连接是否复用和语言，避免混淆样本。
3. 分别检查无会话、匿名防伪Cookie、登录会话、中文以及模型/分类路径；身份信息不得进入公开HTML的源渲染，命中后实际会话仍应有效，个人接口不得进入共享缓存。
4. 若实际首开仍未达标，依据新的网络与绘制证据继续优化，不把目标改为后端响应达标。

## 当前环境阻塞核验

连续三轮目标审计均未取得秒开证据，且需要排除限速/网络状态，相关异步问题尚无答复。最新复查中Chrome脚本读取恢复，前台FCP仍12,088ms、18张卡片存在。独立请求仅包含构建ID的极小静态文件 `/BUILD_ID` 也需1,400ms（200，LAX），不经过Gallery查询或渲染。这一基线已经超过一秒，当前环境不足以支持目标验收。待确认No throttling并具备稳定网络后，重新测真实首开和本版正式登录接口，不将目标改写为缓存处理毫秒数。

## 2026-10-24 独立列补充

Motion / Gallery 已改为共享的纯 CSS 1/2/4 独立列，去掉每批最高列形成的空白。正式两个列表均返回200，浏览器同列间距均16px；本地Motion从24追加36张时原卡片坐标零变动。详见[独立列验收](./independent-columns-validation.md)。

本版正式页面 HTML 首屏仍仅18条，约387KB未压缩/78.6KB gzip；CSS内联约110KB。另测本地完整搜索目录API仍为2,372,778字节，其背景请求在慢网络可能延迟后续追加，但在 hydration 之后启动，不能直接解释首个HTML的TTFB。后续优化需区分首屏响应与完整目录加载，保留正文搜索能力，不能凭猜测改动。

用户已说明暂时不便切换网络，且不确定DevTools限速设置；不能继续把同一确认作为推进前提。当前网络基线与真实绘制仍不达标，原秒开目标保持未完成。

## 2026-10-24 预览分页发布

完整目录改为用户搜索/筛选时按需读取，滚动改为18条预览页；SQL不读取正文。正式版本39eee6a0-aad6-4b80-8231-121713fb9775已发布，50项检查及构建通过，本版正式管理员全链路只读验证通过。分页具体证据见[预览分页验收](./gallery-preview-pagination.md)。当前FCP6,912ms仍不达标；最新静态BUILD_ID请求1,628ms，首开网络基线依然超过1秒。

另发现生产Motion的JS模块发生ERR_CONNECTION_RESET及ChunkLoadError，根错误边界将网络失败显示为not found；这是脚本加载失败而非页面HTTP404。独立列SSR本身显示正确，不能据此宣称本次网络环境的全部前端交互已通过。

## 本轮受阻审计

连续三轮重新核验仍受到同一连接/传输限制：独立列发布时静态构建ID约1,783ms、FCP15,552ms；预览分页发布后静态请求约1,628ms、FCP6,912ms，路由JS模块约116秒；最新同一正式版本的21字节静态请求仍为1,578ms（DNS32ms、TCP334ms、TLS625ms、TTFB1,577ms）。这些样本无法证明首次绘制在一秒内完成。不能把现有缓存内部8ms当成用户端秒开，也不能继续靠重复发布来消除连接条件的影响。

正式部署39eee6a0-aad6-4b80-8231-121713fb9775已完成，无本任务发布进程需要等待；50项测试、类型检查、构建与复审通过。D1和正式管理员会话/查询验证通过。正式浏览器追加18至36张、原卡片零位移、不请求完整目录；前三个预览页与末页已分段验证。

当前仅将“秒开目标”的验收记为受阻，整体目标不标记完成。用户已说明暂时不便切换网络且不确定限速配置，故不重复索要同一确认。需要网络/限速等外部条件变化，才能继续有效验证真实首开；恢复后应保持同一成功标准，重新测前台冷访问的TTFB/FCP与资源下载，而非以缓存响应或本地样本代替。
