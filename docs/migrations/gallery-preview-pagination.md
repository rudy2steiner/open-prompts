# Gallery 预览分页优化

## 问题与范围

旧版首屏 18 张卡片之后，在挂载 250ms 时下载完整正文目录。本地实测完整 JSON 为 2,372,778 字节；正式浏览器在该请求尚未完成时，滚动追加一直等待。此问题属于首开后的资源争用和交互等待，不应与首个 HTML 的 TTFB、FCP 混为一谈。

## 调整

- 默认挂载只保留已有 SSR 首批；滚动使用公开预览分页接口，每页最多 18 条，SQL 不读取提示词正文。
- 下一批追加到独立列，按 ID 去重，结束返回 nextOffset=null，不把结束当作请求失败。
- 用户搜索/筛选时才读取原完整目录，保留正文搜索和原分类逻辑。完整请求优先于过期预览请求，旧响应不得覆盖新目录。
- 预览请求 20 秒、完整目录 60 秒超时；失败可重试，失败不推进分页。
- 从筛选 URL 进入后，清除筛选但完整目录尚未成功时，只重试完整目录，不混用筛选首批与无筛选 offset。
- D1 翻页读取失败返回 503，不以静态兜底数据伪装目录结束。

## 验证

- 50 项自动检查与正式构建通过；独立复审发现的筛选回退 P2 已修复并覆盖回归测试。
- 本地真实 Worker 依次读取 offset 0/18/36/1419：前三批各18条、无重复、无正文；尾页为空且无 nextOffset；重复读取 offset18 为 HIT。
- 各批响应约10.6KB/9.8KB/9.9KB，尾页80字节。
- 本地浏览器默认无完整目录请求；18追加36仅请求9,770字节、约11.6ms，18张已有卡片坐标变动0。
- 本地同版管理员登录、会话隔离、用户统计与审核 API 通过。

## 发布与目标边界

正式版本 `39eee6a0-aad6-4b80-8231-121713fb9775` 已发布，D1 绑定保留、维护关闭。

正式预览 offset0/18/36 分别18条，响应约10.6KB/9.8KB/9.9KB；串行请求约1,276/2,608/1,649ms。首次并发验证有连接错误，串行验证在末页20秒超时；随后单独补验末页返回200、items为空、total=1419、nextOffset=null，耗时2,778ms。正式前三批与末页已分段验证；原整套脚本因网络中断并未一次性全绿，应保留该区别。

本版正式管理员登录、公开页面匿名/登录HTML一致且会话保留、用户统计和审核接口均通过。正式浏览器在脚本加载完成后，从18追加36张，原18张坐标零变动，没有完整目录请求；预览请求200，gzip约3,016字节、2,536ms。页面路由JS模块下载却耗时约116秒，是当前网络交互等待的直接证据。

正式前台 Gallery FCP为6,912ms、TTFB5,158.3ms、HTML缓存处理8ms。首屏没有自动请求完整目录，但JS路由模块仍受网络加载影响。秒开目标仍未完成，不能用小分页体积、本地响应或缓存内部耗时代替验收。
