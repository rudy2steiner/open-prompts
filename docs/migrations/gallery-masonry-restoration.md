# Gallery 瀑布流恢复

## 原因与范围

此前修复 Motion 分批瀑布流空白时，错误地把 Gallery 原来的最短列瀑布流也换成固定独立列，且中屏三列断点被移除。用户反馈 Gallery 变成普通列表后，本次仅恢复 Gallery 原有展示，Motion 保持原样。

## 修复

- Gallery 页面直接使用原 PromptGalleryMasonry，按可用宽度显示 1/2/3/4 列，每张卡片进入当前最短的一列。
- 移除 Gallery 独立列样式和无用包装组件。
- 保留 D1、预览分页、按需正文搜索、封面加载等既有优化。
- 测量几何数据未改变时直接返回，避免 ResizeObserver 重复通知造成无意义重渲染。
- SSR 保持可见网格兜底，不隐藏卡片；浏览器测量后执行原有最短列排列。

## 验证

- 51 项自动检查与正式构建通过，独立复审无阻断。
- 回归测试覆盖 1100px 三列、第4张进入最短第二列、重复相同测量不重渲染。
- 本地浏览器1280px显示四列，卡片实测高度不同（约579、579、630、400px），第5张紧接最短第4列。
- 本地截图已确认高低错落的瀑布流；36追加54张时已有卡片坐标零变动。

## 发布

正式版本 `e15cb85b-cc96-4718-9cf2-4d59d8e8fa39` 已发布。

正式浏览器已完成 hydration，18张卡片全部采用原最短列定位；前四张高度约579/579/630/400px，第5张位于第4列y=416px，确认并非等高普通列表。页面标记为 shortest-column，展示与本地恢复截图一致。
