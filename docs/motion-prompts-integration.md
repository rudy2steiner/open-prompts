# Motion Prompts 整合与验证

## 数据同步

来源为本地 `awesome-ai-motion-prompts/data/videos.json`。运行：

```sh
python3 scripts/import-motion-catalog.py /Users/xuandu/mywsp/awesome-ai-motion-prompts
```

需要 Python Pillow。脚本保留 1000 条作品的原始提示词与来源，生成 `src/data/imports/motion-catalog.json`。对已有本地动图、远程封面和可复用旧封面选取有亮度与细节的帧，生成 `public/motion-posters/catalog-*.webp`。无素材或下载失败时不伪造预览；导入输出会报告封面失败。

当前有 808 张本站真实封面、718 条视频地址；其余 192 条无可用预览素材，显示“暂无预览”。已将真实热度快照接入页面排序，详见下方排序规则。收录文本包含作者提示词与可复用模板，不能把收录视为生成效果或模型的独立核验。

## 页面与交互

- 保留瀑布流，首批 12 条，接近底部 500px 时自动读取下一批，保留按钮及失败重试。
- 类别与 Prompt/Skill 筛选在服务端先过滤再分页；切换筛选会取消旧请求，防止旧结果混入。
- 列表只接收摘要；完整正文只在详情页读取。Hero 也使用摘要，避免 React 客户端边界序列化正文。
- 预览区只播放视频；进入视口后自动静音播放，离开视口或浏览器隐藏时暂停，并遵守减少动态效果设置；标题及“查看提示词”进入本站详情；“作者原文 ↗”独立外跳。
- 全部 1000 条都有详情页与站点地图入口。既有精选 ID 保留。数字 ID 对应的标题 slug 作为规范路径，旧数字链接以 308 跳转到标题路径。
- 视频实际播放前保留封面，滚出视口暂停；缺失预览和播放失败使用明确文案。

## 首屏视频性能

Hero 和默认点赞排序的前 12 条使用原作视频生成的本地短预览：最长 6 秒、静音、20 fps、宽度不超过 480 px。详情页仍播放原作完整视频；其他条目没有本地短预览时沿用原视频。

```sh
python3 scripts/generate-motion-previews.py --ffmpeg /path/to/ffmpeg
```

生成清单为 `motion-preview-videos.json`，文件存于 `public/motion-previews/`，文件名包含来源和编码配置哈希，使用长期缓存。更新热度或原视频后重新运行生成脚本，补齐新的默认首屏。清单只有在原视频地址匹配时才生效。

视频进入可视范围后自动播放，离开后释放视频请求并恢复封面。统计脚本延后到页面加载完成后执行，避免拖慢首屏资源加载。

## 首帧保护与详情渐进视频（2026-10-23）

- 封面只在 `requestVideoFrameCallback` 确认提交了非零进度帧后隐藏；旧浏览器需已解码数据和时间推进。`playing` 事件本身不能作为首帧就绪证据。
- 已播放后的缓冲不重置画面；播放器挂起时保留当前帧。没有真实帧时继续保留封面，不叠加媒体 Retry。
- 有有效短预览的详情先播放本站短预览，实际短预览出帧后才请求完整原片。完整播放器先隐藏，按预览时间准备并出帧后才接管；不通过替换同一个播放器的 `src` 来切换。
- 完整原片未就绪时预览保持播放，原片错误保留预览。用户暂停不会被交接自动抢播；预览 seek 会取消旧交接并重新对齐，播放速率同步。移出可视范围释放两个播放器。
