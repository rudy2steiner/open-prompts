## Why

Open Prompts 目前以「提示词画廊/复用」为主，用户需要跳转到外部工具才能验证提示词效果，导致从发现到产出链路长、转化低。支持在站内基于模版直接生图，可以把“浏览提示词”升级为“可立即产出的创作工作流”，提升留存与付费空间（自托管 Key / 订阅）。

## What Changes

- 在提示词详情/模态框中新增「基于模版生图」入口：选择模版、模型、尺寸/比例与可选参数后，站内发起生成任务并展示结果
- 新增模版变量系统：模版可包含占位符（如主体/风格/背景/镜头/负面词等），用户在生成前填写或选择预设
- MVP 采用 API 直连 provider + 轮询获取结果：展示生成状态与结果（不做持久化历史/任务表，后续再补）
- 生图 provider 支持多个，默认内置 `atlascloud` 与 `replicate` 接口（可扩展）
- 新增自托管 Key 与订阅两种使用方式的接入点（权限与配额控制）

## Capabilities

### New Capabilities

- `template-image-generation`: 基于提示词模版（含变量）在站内直接生图，并返回可展示/可下载的图像结果
- `prompt-template-variables`: 支持提示词模版变量定义、默认值/枚举、用户输入校验与渲染为最终提示词
- `generation-jobs`: 生成任务的创建、状态查询、结果存储/引用、历史记录与失败重试（后续迭代补齐，MVP 可不做持久化）

## Impact

- 前端（Next.js + Tailwind CSS）：提示词详情页/弹窗新增模版表单、模型/参数选择、任务进度与结果画廊；新增“我的生成历史/任务”页面（或在用户中心内）
- 后端/API（Next.js routes + Supabase）：新增生成相关 API（创建任务/查询任务/拉取结果）；对接一个或多个生图提供方（自托管 Key / 订阅）并抽象 provider
- 数据层（Supabase Postgres + RLS）：MVP 可不落库；后续迭代再新增生成任务、生成结果（以及可选模版定义）的存储结构与访问控制
- 模版存储：模版可先基于本地 JSON 文件（随代码发布）提供；后续可选演进为 Supabase 表以支持在线编辑与用户自定义
- 对象存储（Cloudflare R2）：MVP 可先使用 provider 返回的可访问 URL；后续迭代再做 R2 落盘与签名下载/缓存策略
- 安全与成本：API Key 加密存储、速率限制、配额与计费埋点；对外链图片与用户内容做基础风控（可先最小化）
